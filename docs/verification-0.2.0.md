## 보안 회귀 검증

- 세션 저장 중 Lock이 발생해도 완료 시 Unlock이 되살아나지 않음.
- 다른 extension context의 Lock, popup dispose, 복원 중 Lock 처리.
- 세션 항목 삭제 실패 시 epoch로 기존 세션을 무효화.
- 초기화 시 손상된 메타데이터를 만나면 키와 복호화 참조를 비우고 잠금 유지.
- 신규 비밀번호 7자 거부, 8자 허용.
- v1의 짧은 기존 비밀번호로 Unlock 가능. 기존 레코드는 수정할 때만 v2 전환.
- 레코드 종류, Vault ID, salt, KDF 매개변수, IV, 암호문, 시간, 버전 검증.
- 삭제 기록을 별도 항목에 먼저 저장. worker 처리 전에도 오래된 secret을 숨기고, 지연 수정 후에도 삭제 유지.
- 같은 브라우저의 경쟁 수정 직렬화 및 오래된 편집 거부.
- 서로 다른 Vault 메타데이터 보존과 충돌 시 쓰기 중단.
- Chrome이 객체 필드 순서를 변경해도 메타데이터 비교와 세션 복원이 정상 동작.

## Chromium E2E 범위

Playwright 1.63.0의 Chromium 153.0.8010.12, 개인 프로필과 분리된 임시 persistent profile 두 개에서 빌드된 확장을 로드했습니다. 확장 페이지를 380×600 viewport의 탭에서 열어 popup 생명주기를 재현했습니다. Chrome 툴바의 실제 popup 창과 OS 사용자 로그인 세션까지 검증한 것은 아닙니다.

- 생성, 키 추가, 기본 마스킹, 10초 자동 숨김.
- Copy 성공 피드백과 별도 로컬 테스트 페이지에서 클립보드 값 일치 확인. 확장 프로그램에 추가 권한을 부여하지 않음.
- API KEYS만 스크롤, 헤더 위치 고정, 스크롤바 6px, 전체 문서 높이 제한.
- Secret 원문으로 검색 불가.
- Sync 데이터에 샘플 비밀번호·키·서비스명·이름 원문 없음. storage.local 비어 있음.
- 확장 페이지를 닫고 다시 열 때 Unlock 유지.
- 잘못된 비밀번호 거부 및 올바른 비밀번호로 Unlock.
- 두 프로필 간 암호문 전달 후 복원, 삭제 전달, 오래된 데이터 재전달 후 삭제 유지.
- 브라우저 context 완전 종료/재시작 후 Lock 및 세션 키 없음.
- 확장 내부 개인정보처리방침 링크 동작.

두 프로필 간 데이터는 테스트가 명시적으로 전달했습니다. 실제 Chrome Storage/onChanged는 사용했지만 **Google Sync 서버를 통한 전달과 오프라인 복귀는 미검증**입니다.

## 배포물

`npm run package`로 `release/envpin-0.2.0.zip`을 생성합니다. ZIP에는 런타임 파일 11개만 들어가며, 테스트·개발 의존성·소스맵·문서 원본은 포함하지 않습니다. SHA-256은 같은 경로의 `.zip.sha256` 파일을 확인하세요. ZIP은 Git에 커밋하지 않습니다.

웹스토어 스크린샷과 홍보 이미지는 샘플 데이터만 포함하며 육안으로 확인했습니다. [스토어 제출 초안](../store/listing.md)과 [개인정보처리방침](../PRIVACY.md)을 함께 사용하세요.

## 남은 배포 조건

1. 같은 Google 계정, 동일 확장 ID를 사용하는 실제 PC 두 대에서 [수동 QA](manual-qa.md)의 Google Sync 항목 확인.
2. Chrome 툴바 popup, 기본 키보드 탐색 및 OS별 동작 수동 확인.
3. 웹스토어 대시보드의 개인정보처리 신고와 실제 구현 일치 확인 후 제출. 자동 승인 또는 독립 보안 감사 완료를 의미하지 않습니다.
