# 동기화 충돌 대응

Envpin 0.2는 Vault 식별자와 보존용 메타데이터를 사용합니다. 서로 다른 Vault가 같은 Chrome Sync 저장소에 나타나면 비밀번호 검증 전에 충돌을 알리고 쓰기를 중단합니다. 자동으로 하나를 선택하거나 기존 암호문을 삭제하지 않습니다.

## 충돌 메시지가 나타나면

1. 영향을 받은 기기에서 Envpin 사용을 멈춥니다. 새로운 Vault를 만들거나 저장소를 초기화하지 마세요.
2. 모든 기기가 같은 Envpin 버전을 사용하는지 확인합니다. 0.1 기기로 수정·삭제를 계속하지 마세요.
3. [GitHub Issues](https://github.com/rheeeuro/envpin/issues)에 버전, 기기 수, 작업 순서, 오류 문구만 전달합니다. 비밀번호·키·스토리지 덤프는 게시하지 마세요.
4. 원본 데이터를 보존한 별도 환경에서 Vault별 메타데이터와 암호문을 분리해 검토해야 합니다. 현재 자동 복구 UI는 없습니다. 저장소를 임의로 편집하지 마세요.

기존 v1 레코드는 암호화 당시 Vault ID가 없으므로 정확한 소속을 알려면 올바른 비밀번호로 복호화 검증해야 합니다. v1 비밀번호가 8자 미만이어도 잠금 해제할 수 있습니다. 기존 레코드는 읽기만 할 때 변경하지 않으며 수정 또는 삭제할 때 v2로 전환합니다.

## 보장 범위

- 새 Vault는 활성 메타데이터보다 먼저 Vault별 메타데이터를 저장합니다. 동시 생성 충돌이 발생해도 복호화에 필요한 salt와 verification을 보존합니다.
- 삭제는 같은 ID의 수정보다 우선합니다. 별도 `deleted:<id>` 항목에 암호화된 삭제 표시를 무기한 보관하고 원래 키 내용은 제거합니다. 오래된 수정은 이 별도 항목을 덮어쓰지 못합니다.
- Chrome Sync에는 전역 트랜잭션이 없습니다. 다른 기기에서 발생한 원격 쓰기와 로컬 쓰기를 완전히 원자적으로 묶을 수는 없습니다.
- 삭제 기록의 수정 시각과 상태는 암호화된 내용과 함께 인증됩니다. 잠긴 worker는 형식 검사와 우선순위 비교만 할 수 있고, 암호학적 검증은 Unlock 뒤 수행합니다. Sync 저장소 자체를 조작할 수 있는 공격자에 대한 가용성 보장은 제공하지 않습니다.
- 구버전 클라이언트나 사용자가 저장소를 직접 삭제한 경우까지 복구를 보장할 수 없습니다. 0.2로 전환할 때 모든 기기의 확장 프로그램을 업데이트하세요.
